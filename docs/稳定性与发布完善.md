# 稳定性与发布完善

日期：2026-10-04。本文记录我在分层重构之后补齐的五个小版本及验收边界；每一步单独提交，便于回退。

## v0.15.0 单张图片后台处理

我将颜色基础预览、颜色更新、裁剪旋转、尺寸更新、背景基础预览、完整处理和编辑页全屏计算放入后台。后台接收 QImage 与参数快照，返回独立 QImage；QPixmap 创建、画布更新和历史提交仍在界面线程。

`application/imagetask` 共用 QtConcurrent 和 QFutureWatcher，一次保留一个正在计算的请求与一个最新待处理请求。拖动滑块时，中间参数被合并，过期结果不会刷新画面。参数面板释放后，后台只持有值，不再回调已销毁的界面。模式切换仍共用常驻画布，等待计算时保留上一帧。

完整处理时禁用重复操作，状态栏提供“取消处理”。取消会丢弃本次结果并保留上次成功图片；正在执行的 OpenCV 调用不能被强行打断。处理成功后统一更新图片、参数和历史；撤销或重做失败／取消时恢复历史位置。

六项 CTest 在普通和 200% 显示缩放下通过。新增后台任务测试覆盖线程、最新请求合并、取消后的新请求、异常恢复、真实灰度输出、原图保护和任务对象释放；编辑交互测试等待后台完成，仍验证滑块释放前更新、模式切换和撤销重做。

Qt 的普通 `QtConcurrent::run` 不能保证中断已经开始的计算，取消语义依据 [QFutureWatcher 官方说明](https://doc.qt.io/qt-6/qfuturewatcher.html)。打开图片读取与 PNG 保存仍使用原有文件入口，本次后台化针对图像处理计算。

## v0.16.0 未保存修改保护

我使用 QUndoStack 的 clean 状态记录成功保存的位置。新图片打开成功后清空历史；保存成功才标记 clean。撤销离开保存位置会显示“未保存”，重做到保存位置会清除标记。编辑页尚未提交的草稿也纳入保护。

关闭窗口或成功选择另一张图片后，提供“保存／放弃修改／取消”。选择保存时，先后台处理最新草稿，再保存完整结果；处理失败、写入失败、取消选路径或取消计算，都不继续关闭或替换图片。选择文件时直接取消、选到坏图，不触发丢弃修改。保存成功通过状态栏显示实际输出路径。

我同时修正了窗口释放顺序：先断开依赖主窗口成员的回调，再清理编辑面板，避免子控件释放过程访问已销毁状态。

七项自动检查通过，200% 显示缩放下也通过。新增检查覆盖关闭／打开／保存取消、保存状态、撤销重做 clean 标记、放弃后更换图片，以及保存编辑草稿后关闭。

## v0.17.0 独立批量参数与预设

我给批量页面添加独立参数区：保持尺寸、固定宽高、限制长边、按百分比，以及灰度、亮度、对比度、背景模式、纯色、边缘柔和度和模糊强度。默认可沿用主页完整参数，也可以随时点击“使用主页参数”。修改批量参数不改变主页图片。

长边和百分比由领域层按每张图片的几何结果计算，保持比例；长边模式默认不放大小图，可显式开启。任务启动后复制参数，运行期间禁用参数区。原文件保护、失败继续、取消和报告功能保持原有语义。

内置预设为保持原图／转换 PNG、长边 1200 px、灰度、人像背景移除；自定义预设通过 QSettings 存储，名称支持中文，提供保存、同名更新和删除。预设保存尺寸策略、颜色、几何和背景参数与归一化笔触。图片替换背景只在当前任务中沿用，保存这类预设时给出明确提示，不静默丢失背景图片。不同图片中的裁剪及画笔位置需要先少量试运行。

八项自动检查通过，200% 显示缩放下也通过。新增检查覆盖横竖比例、几何后尺寸、小图不放大、百分比、颜色组合、任务快照、预设往返／删除／坏数据、超限输出及独立界面；我检查了批量页面渲染结果。

## v0.18.0 GitHub 自动构建与测试

我新增 Windows 工作流，推送 main、提交 PR 或手动运行时，用 MSVC x64、Qt 6.11.1 和 OpenCV 4.13.0 构建 Release，运行普通与 200% 显示缩放的全部测试，上传测试记录。并发构建限制为两项，同一分支的旧运行可以被新提交取消。

OpenCV 使用官方 Windows 发行包并核对 SHA256；构建工具使用固定提交标识，Qt 和 OpenCV 版本固定。工作流只申请读取源码权限。首次远端执行的结果在任务完成后记录，配置文件已存在不等于远端测试已经通过。

依赖依据：[Qt 安装工具说明](https://github.com/jurplel/install-qt-action/tree/v4)、[OpenCV 4.13.0 官方发行](https://github.com/opencv/opencv/releases/tag/4.13.0)、[GitHub 持续集成说明](https://docs.github.com/en/actions/get-started/continuous-integration)。

修复后的 [GitHub 运行](https://github.com/GreenLoong/pixel-workshop/actions/runs/37200344587) 已完成：依赖安装、Release 编译、普通和 200% 显示缩放的八项测试均通过。

## v0.19.0 Windows 交付候选版

我给可执行文件和 QApplication 加入一致的版本信息，使用官方 windeployqt 部署 Qt 与编译器运行库，补充 OpenCV、Qt 和人像模型许可证。打包要求源码已经提交，生成独立新目录、ZIP、压缩包 SHA256 和含版本／提交／逐文件哈希的 manifest.json，保留以前的包。

独立 PixelWorkshopCheck 共用应用层处理入口，检查中文路径 PNG 往返、大图后台处理、灰度／亮度／尺寸组合、Alpha 保持、重名编号、坏图继续、取消与内嵌模型。不在日常程序启动时运行自检。验收脚本清除子进程中的开发路径，只使用包内 DLL 与 Windows 系统目录，检查主窗口创建和正常关闭，再写入 verification-result.json。

本机九项 CTest 在普通与 200% 显示缩放下全部通过。PNG 往返核对先统一 QImage 内存格式再比较像素，避免 RGBA8888 与解码器返回的 ARGB32 排列差异造成误报。

工作流增加 ZIP 上传和独立 Windows 运行机解压验收；该运行机不安装 Qt/OpenCV，但预装系统组件及 Visual C++ 运行库。自动结果以对应 Actions 记录为准，不能替代使用者电脑的鼠标、触控板与大图体验。实际设备可用，取得候选包后按[另一台电脑验收](另一台电脑验收.md)检查，完成后再确认稳定版。
