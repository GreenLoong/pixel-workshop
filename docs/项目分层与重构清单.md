# 项目分层与重构清单

日期：2026-10-04。文档版本：1.1。适用项目：pixel-workshop，C++17 / Qt 6 / OpenCV 4 桌面工具。

## 分类方案与目录职责

我按现有代码职责划分四层，保留 Qt Creator 的原构建入口 `ImageBatchTool/CMakeLists.txt`。

```text
ImageBatchTool/
├─ CMakeLists.txt
├─ src/
│  ├─ main.cpp
│  ├─ domain/
│  │  ├─ imageprocessor.h/.cpp
│  │  ├─ geometryprocessor.cpp
│  │  ├─ backgroundprocessor.cpp
│  │  └─ humansegmentation.h/.cpp
│  ├─ infrastructure/
│  │  ├─ imagefiles.h/.cpp
│  │  ├─ imageconversion.h/.cpp
│  │  └─ modelresources.h/.cpp
│  ├─ application/
│  │  ├─ imageprocessing.h/.cpp
│  │  ├─ batchjob.h/.cpp
│  │  └─ backgroundpreview.h/.cpp
│  └─ presentation/
│     ├─ windows/       主窗口与 Designer 文件
│     ├─ pages/         编辑会话、模式导航与草稿历史
│     ├─ dialogs/       参数面板、批量对话框与 Designer 文件
│     └─ widgets/       预览、选择框、画笔、外观与滑动条策略
├─ resources/
│  ├─ icons/
│  ├─ styles/
│  ├─ models/            ONNX、许可与来源说明
│  ├─ indicators.qrc
│  └─ appicon.rc
├─ cmake/
└─ tests/
docs/
tools/
```

| 目录 | 职责 | 依赖约束 |
| --- | --- | --- |
| domain | 处理参数、几何、颜色、背景合成与分割 | 标准库与 OpenCV；不包含 Qt 或界面 |
| infrastructure | 图片保存、模型资源、数据格式与内存适配 | Qt Core / Gui 与领域数据类型；不访问控件 |
| application | 单张处理流程、批量扫描与任务生命周期 | 领域与基础设施；不依赖 Widgets |
| presentation | 显示、用户输入、草稿、历史及结果提交 | 应用服务与领域参数；不负责模型文件加载 |
| resources | 图标、QSS、模型及许可证 | 通过资源别名访问；别名保持不变 |
| cmake / tests / tools / docs | 构建兼容、验证、交付与开发记录 | 测试链接实际模块实现 |

公共代码按职责归属相应模块，没有单独添加无内容的工具库。人像推理直接使用现有 OpenCV dnn，因此与其他图像算法归入领域模块；模型文件的读取与摘要校验归入基础设施。

实际构建依赖：`pixel_presentation → pixel_application → pixel_infrastructure → pixel_domain`。源码允许上层使用下层值类型和数据适配器：表现层直接使用 Options、文件保存及替换背景图片的格式适配；模型读取和图像处理流程由应用层协调。下层不引用表现层，应用和基础设施不依赖 Widgets；领域纯算法测试只链接 `pixel_domain`。资源作为对象库编译一次，再进入需要资源的可执行文件，避免静态库资源注册代码被链接器忽略。

## 重构清单

第一阶段已迁移源码、资源与环境验证文档，同步修正 C++ include、Designer 自定义控件头文件、CMake、打包许可证路径和文档引用。构建目标取代应用与测试中重复的源码清单。

| 操作 | 原内容 | 重构结果与理由 |
| --- | --- | --- |
| 合并 | 应用与多个测试重复列举、编译同一源码 | CMake 按四个模块建立目标；测试直接链接实际实现 |
| 拆分职责 | ImageProcessing 同时加载模型、转换内存和调用算法 | ModelResources 管理模型读取、校验和共享；ImageConversion 管理步长与所有权；应用入口协调调用 |
| 拆分职责 | BackgroundDialog 同时定义画笔画布、计算结果和管理控件 | BrushPreview 归入 widgets；BackgroundPreview 归入 application；对话框管理工具状态、后台调度和结果显示 |
| 拆分职责 | MainWindow 内部构造并同步整套缩放控件 | ZoomControls 绑定预览，集中管理百分比、滑块和按钮同步；对象名与样式保持一致 |
| 合并 | 尺寸页创建整图查询尺寸；裁剪页自己计算旋转后宽高 | geometrySize 与 transformGeometry 共用画布尺寸及裁剪舍入；查询不分配图片 |
| 合并 | 算法与两个尺寸界面分别使用 4000 万常量 | MaxOutputPixels / validOutputSize 作为领域规则，界面与运算共用 |
| 合并 | 四个预览入口重复缩略图与尺寸边界规则 | PreviewImage 只收敛已有规则；编辑预览最大边 1280，独立背景对话框仍为 1024 |
| 合并 | 单张保存入口和 ImageFiles 重复补 PNG 后缀 | 后缀、独占创建、编号和失败清理由 ImageFiles 统一处理 |
| 删除 | resizeByPercent / displayedImageSize 声明与实现 | 全部源码、测试及文档无调用；百分比输入仍由 ResizeDialog 转为目标像素，缩放显示仍由 PreviewLabel 管理 |
| 删除 | ToneDialog::initial_ | 初始化后从未读取，取消保护由草稿会话和工作参数实现 |
| 删除 | ResizeDialog::setupFramelessWindow | 单次转发没有独立规则，直接在构造时调用已有 DialogAppearance |
| 删除 | 主页始终隐藏的尺寸、灰度、调色、恢复按钮及连接、状态更新 | 可见操作已集中到编辑页；删除残留的 Designer 节点和运行时隐藏逻辑 |
| 删除 | 处理结束时再次判断结果是否与输入共用数据 | 几何入口已复制输入，其余步骤在独立结果上运算；原图保护和等价检查验证所有权 |
| 归档 | 主窗口和编辑页内嵌 QSS、源码目录中的环境验证文档 | 样式放入 resources/styles，验证示例放入 docs；资源与文档引用同步更新 |

我保留 Qt 图形视图、QSignalBlocker、QProxyStyle 绝对滑动条、QThread 工作对象、独立参数对话框、几何页的 initial_ 和历史命令。它们分别承担平移范围、信号联动、官方滑块策略、线程生命周期、独立交互验证、未修改参数识别和撤销语义，已有检查也在使用这些行为。没有添加基类框架、服务定位器或为每个函数建立接口。

源码引用路径按新目录更新。两项无调用辅助接口 resizeByPercent 与 displayedImageSize 已删除；主要 process / processImage、Options、BatchJob、窗口与对话框调用语义保持一致。MainWindow 中通过 Qt 元对象调用的旧槽名称仍保留，以免改变既有调用与检查。

核心处理链现在保持以下关系：

```cpp
// rgb 是应用层持有的 RGB888 / RGBA8888 QImage，活到 process 返回。
const cv::Mat source = ImageConversion::rgbView(rgb);
auto processing = options;
if (processing.background != ImageProcessor::BackgroundMode::None
    && processing.segmentation == ImageProcessor::SegmentationMethod::Human)
    processing.humanModel = ModelResources::humanModel();
const cv::Mat result = ImageProcessor::process(source, processing);
return ImageConversion::copyImage(result); // 输出拥有独立内存。
```

## 行为与验证范围
